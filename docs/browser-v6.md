# V6 浏览器与站点账号

本增量基于 `dev_v0.3.3` 的模块边界，参考 `dev_v0.3.2` 中 Playwright 的操作实现。浏览器能力走 Desktop → SDK → 扩展 query/command → SiteExtension → App Server 宿主服务 → 隔离 Browser Worker，不由 Desktop 加载 Runtime 或 Playwright。

宿主账号业务位于 `com.javaclaw.server.site.account`，组合现有 Managed Extension Store 与 Vault。持久化基础包不反向依赖 Vault，H2 连接所有权和公共 SDK 边界保持不变。

## 旧目录升级

Site 清单现为 `6.0.0 / revision 2`，权限上限 revision 同步为 2。启动时只允许两份已审核的完整历史清单迁入：旧站点工具清单，以及曾增加浏览器工具但仍沿用 `5.0.0 / revision 1` 的清单。集合顺序不影响匹配，未知字段差异、损坏记录、第三方身份或版本倒退仍拒绝启动。

迁移在现有目录事务中原子更新清单与版本，不删除数据或重写历史 SQL migration。启停状态、状态 revision、托管网站和账号文档、密封引用及原命令回执保留；重复启动不会再次改变记录。旧 Turn 的扩展 revision 在升级后失效，不能使用旧冻结身份调用新增权限。遇到旧版的“内置扩展目录与发行版描述不一致”错误时，使用修复版本重新构建并启动即可自动执行这条精确迁移，不需要清空数据目录。

## 能力发布门禁

浏览器镜像必须同时具有已验证的 Worker 镜像和当前平台 `browser-interactive-v1.capability` 标记，宿主才发布常驻可见浏览器可用状态。缺少标记时账号管理仍可使用，浏览器入口显示真实不可用原因，不回退无沙箱子进程。

本机 macOS 26.5.2 arm64 的私有 bootstrap namespace 探针返回 125，未通过独立可见 Chromium 的隔离启动验证。因此当前机器不发布可见浏览器能力。证据见 [原生探针记录](evidence/browser-interactive-native-2026-09-14.md)。Windows、Linux 及其他 macOS 版本尚不能据此记录宣称可用；需各自通过原生启动、实例隔离和进程树回收门禁。

当前原生进程树隔离证明状态在三个平台均为 `UNVERIFIED`，生产与 Packaging smoke 共用独立拒绝门禁。现有进程监护测试覆盖宿主发起的受控关闭与已观察到的子进程；Worker 根进程自行退出时，即使退出码为 0，也拒绝成功回执。这些测试不证明瞬时 fork、setsid 和重挂父进程的所有逃逸情形。仅窗口能启动不足以发布能力标记；可见浏览器的原生验收尚未完成。

## 运行与授权

- 一条对话最多一个浏览器会话，一个会话最多八个标签页。每次操作使用同一会话 actor 串行执行。
- 页面可以跨 Turn 保留；Turn 结束只释放执行租约。15 分钟闲置关闭会话。
- AI 租约与人工租约分开。用户接管会取消旧操作、阻断旧观察与网络结果；交还后旧元素引用和截图代次失效。
- 浏览器专用授权绑定 Workspace、Thread 和精确 HTTPS Origin，不扩展其他工具的网络权限。Turn 创建事务固定授权 ID 与版本，不依赖系统墙钟先后；当前 Turn 的快照不随确认操作改变，新增授权由宿主请求新 Turn 续接。
- 授权版本与 Turn 创建在同一个 Thread 事务锁下冻结，系统时钟静止或回拨也不会把新来源补入旧 Turn；续接和幂等恢复使用各自已保存的快照。每个 Thread 最多同时授权 128 个来源，达到上限后须先撤销已有来源。兼容旧版本超过上限的数据时，普通 Turn 仍能创建，浏览器快照仅按授权版本时间倒序及 ID 固定排序保留前 128 个来源，其余来源不会获得该 Turn 的浏览权限。
- 新 Turn 继承原任务剩余 token、工具和墙钟预算。持久续接链接指向原用户消息，不重复追加消息；旧工具批次中尚未执行的调用提交明确的未执行结果。
- 撤权同时检查当前授权版本和每次 Broker 请求，不能只依赖启动时的允许列表。私网、WebSocket、Service Worker 和 HTTPS 限制沿用既有边界。
- 动作在执行前写入有身份绑定的账本。没有成功回执的点击、提交、上传不自动重放；已完成动作只恢复已保存结果。
- 页面动作被新来源阻断并返回 Worker 失败时，宿主仍处理当前租约的来源确认。工具结果明确保留“原操作未确认”，不生成 EffectReceipt；只有实际持久化的续接请求才能触发新 Turn。

撤销后重新批准使用新的授权身份，不能恢复旧 Turn 的权限。

## 账号与秘密

账号文档位于 Site 的 Managed Extension Store，用户名密码与 storage state 使用不同 Vault 密封引用。Cookie、localStorage 和 IndexedDB 不进入公开 DTO、工具参数或模型上下文。

账号安全版本在密码、注销、禁用等操作时前进；正常登录态续存仅更新状态版本。保存前后都校验站点 authority 和写租约，迟到保存不能恢复已注销账号。同库事务提交网页登录捕获的凭据和登录态，避免部分成功后丢失登录状态。

模型填写账号只提供当前账号绑定的有效元素身份。宿主核验精确登录 Origin 后，通过 Worker 私有帧提供秘密字节。网页捕获仅在用户明确进入保存流程并选择当前登录表单后执行；无法可靠捕获时可仅保存登录态，在管理中心补录密码。

网页保存流程要求打开会话时已经绑定账号，并处于人工接管状态；匿名会话不能直接另存为新账号。账号切换需关闭原会话再打开隔离上下文。捕获只接受当前文档中可见、同一标准表单内的用户名和 password 输入；表单消失、OAuth 或无密码登录使用“仅保存登录态”。手动改密时用户名也需重新输入，管理页不回读用户名或密码。

登录态保存范围为 Cookie、localStorage 和 IndexedDB；sessionStorage 不跨关闭恢复。管理页分别展示凭据与登录态的保存时间，普通账号重命名不刷新这两个时间。

## 网站会话设置

管理中心的“网站会话”采用上方网站列表、下方所选网站配置的布局。列表显示名称、网址和启用状态，沿用服务端分页；点击网站后才显示详情。创建入口为“新建网站”，创建成功后自动定位并选中新网站。

下方分为“基本信息”“账号与登录”“高级配置”，默认展开基本信息，同一时间展开一个分区。账号区跟随上方选择，不再单独维护网站目录。“网页登录”按需读取所选网站的隔离登录会话；加载失败可局部重试，不影响基本配置。

HTTP 凭据绑定和私网授权位于高级配置。通过“管理共享凭据”打开独立窗口，可以创建、轮换或永久清除 Site 命名空间的共享 HTTP 凭据；该凭据库与每个网站账号的用户名密码不同，创建共享凭据不会自动绑定当前网站。

切换网站、分页、新建或展开其他配置分区时，未保存草稿须先保存或明确放弃。保存期间禁止切换操作目标；服务端通知和迟到响应不会覆盖当前草稿。普通保存失败保留编辑内容，秘密仍在提交后立即清空，关闭凭据窗口时清除临时输入。

网站页关闭后释放通知订阅；重新打开时重新检查扩展目录并读取最新数据。页面定义未变化时保留网站选择和展开分区，已发送的保存操作不会因重开而再次执行。

布局由 Desktop 平台组合既有 ViewSchema 节点，表单、绑定、revision 校验和危险操作确认继续通过 SDK。`login.view` 接受可选 `siteId` 以筛选当前网站，旧无参数调用仍列出当前 Workspace 的会话；没有新增数据库 migration 或执行权限。

交互验收和两种窗口尺寸的截图见[网站会话设置页验证](evidence/site-settings-layout-validation.md)。登录会话采用按需查询和显式刷新，不持续推送状态。

### 从浏览器添加网站

“添加地址”使用独立的 Workspace 登记会话：输入 HTTPS 地址，打开隔离浏览器并完成人工登录，再点击“完成添加”。
该操作用于登记网站与本次登录信息，不替用户向外部网站注册账号。原有“新建网站”继续支持手动配置。

窗口展示当前网站、网站名称和本次捕获的登录表单候选，不展示用户名、密码、Cookie 或 storage state。
保存时一次创建网站及默认账号，并将登录态和用户选中的本次凭据密封入 Vault；只有成功提交后才在列表中选中新网站。
缺少可用表单时可以只保存登录态。已经登记的同 Origin 网站不能通过此入口覆盖账号或秘密。

跳转或页面依赖涉及其他 HTTPS Origin 时仍由 Broker 阻断。用户必须在登记窗口明确添加所需的精确 Origin；
网页发现的地址只是待授权提示，不会自动获得权限。来源授权仅用于本次登记，不替聊天 Thread 创建 BrowserGrant，
也不授予私网访问。SSO 登录页的密码不能作为另一个 Origin 的网站密码保存。

关闭或取消未完成的窗口不会生成空网站。临时登记受期限、会话数和资源预算约束，保存前复核来源、控制代次和页面版本；
确认后又发生导航时要求重新读取当前页面。保存回执丢失时读取会话结果恢复，不自动重放保存。

实现沿 `Desktop → SDK → Site Extension → App Server → Browser Worker`，不借用聊天 Thread，也不先写占位网站。
网站、默认账号、密文引用和完成回执使用同一数据库事务提交，不新增数据库 migration。
实际登录态范围仍为 Cookie、localStorage 和 IndexedDB，不包含 sessionStorage；保存登录态不代表服务器能判断外部网站登录成功。

此入口沿用上文的原生可见浏览器发布门禁。缺少经过验证的 Worker 能力时会明确拒绝启动，不回退到用户个人浏览器配置。

## 附件与模型图片

上传只读取当前对话已拥有的附件，不接受宿主文件路径。下载和截图通过现有 Attachment 服务保存；聊天和预览基于成功 ToolResult、原 ToolCall 身份、Workspace 和 Thread 共同校验来源。

聊天浏览器入口本次没有新增独立文件选择器；上传动作使用当前对话已经提交的附件引用。预览、上传及模型图片读取拒绝同一 Turn 内重复、未完成或后到的调用身份。

`ModelMessage` 的图片是类型化附件引用；Provider 请求边界才读取字节。Responses 持久续接状态保存引用，不保存 base64 图片；Spring AI 按用户或工具观察映射 Media。运行时与历史回放复用相同的宿主图片投影。

模型图片能力由具体 Provider/模型声明，未知值不当作支持。文本模型继续接收文本观察，坐标操作要求图片能力已声明。浏览器截图使用 PNG；其他用户图片仍受宿主图片解码器、尺寸及字节预算限制。

截图当前仅对未接触秘密的匿名助手会话开放。加载账号或登录态、填写或捕获凭据、人工接管都会把会话标为私有；之后截图拒绝并返回 `BROWSER_SCREENSHOT_PRIVATE_SESSION`。DOM 密码遮罩无法证明 Canvas、图片或页面其他区域没有秘密，因此本次实现没有开放已登录会话的视觉操作。这是已知功能限制，不能用匿名会话截图测试代替验收。
