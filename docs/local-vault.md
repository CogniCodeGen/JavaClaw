# 本地密钥库

## 保存位置

App Server 将 API Key、MCP Token、网站秘密等凭据的 AES-256-GCM 密文与解密主密钥保存到同一个本地 H2 数据库：
`data-v6/javaclaw.mv.db`。生产流程不读取、写入或删除 macOS Keychain、Windows 系统凭据或 Linux Secret Service 中的主密钥。

Desktop 继续通过 Presenter / SDK / RPC 调用 Vault，不能直接连接数据库或读取、复制、导出秘密。凭据反重放、Provider
原子保存、双版本冲突、运行时切换和撤权门闩保持原有机制。临时明文及主密钥副本使用后清零。
H2 的原始 SQL 文件和终端跟踪均关闭，避免底层错误把密钥写入诊断；服务端继续返回脱敏失败信息。

主密钥和密文位于同一数据库，完整数据库副本包含解密材料。保密边界依赖现有私有目录、文件权限和备份访问控制。
不要单独替换主密钥表或混用不同备份的密文及密钥。

## 仅支持新数据库

本实现仅适配全新数据库及其后续重启，不升级旧数据库，也不导入旧钥匙串或凭据。
生产启动入口在执行建表前只读检查已有数据库版本；旧库会明确拒绝启动，提示使用全新的 `data-v6` 目录。
拒绝时不修改旧库的表、数据或版本记录，不自动清除已有数据。

新库沿用现有有序建表、checksum 和校验机制，V011 只定义本地主密钥表；V001～V010 原文不变。
通用 schema 执行器保持原有行为，生产本地 Vault 的入口额外限制为新库或已完成本地格式初始化的库。
未完成新库初始化且还未记录 V011 的目录不自动续建，应换用新的空目录。

可以显式使用 `-Djavaclaw.data.root=<新的绝对路径/data-v6>` 启动，然后重新配置模型服务和密钥。
数据根仍须以 `data-v6` 结尾。现有用户数据目录不会由本轮实现自动移动、删除或重建。

| 数据状态 | 行为 |
| --- | --- |
| 全新数据目录 | 建表并生成本地主密钥，不访问系统凭据服务 |
| 本地格式的新库重启 | 从同一数据库加载主密钥，原模型配置继续可用 |
| 旧版本数据库 | 只读识别后拒绝启动，不执行升级或导入 |
| 本地主密钥缺失或无效 | Vault 锁定，保留已有密文，不回退系统或静默生成替代密钥 |
| 本地存储暂时不可用 | 保存明确失败；恢复后可刷新密钥库状态再重试 |

## 事务与恢复

主密钥轮换沿用既有顺序：先持久化候选主密钥，再在单个 Vault 事务中更新密文、活动指针和幂等回执，提交后切换运行时，
最后清理旧的本地主密钥。事务失败保留原凭据和主密钥，并清理候选。健康检查和测试显式注入的保护器保持原语义。

数据库恢复可用后，通过“管理中心 → 安全与连接 → 密钥库 → 刷新并重新解封”重新加载本地主密钥。
该操作不会重置或删除凭据；“永久重置密钥库”仍是独立的危险操作，需要既有明确确认。
