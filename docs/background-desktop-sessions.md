# 桌面会话

JavaClaw 使用目标绑定的桌面会话观察和操作其他应用。首版平台是 Windows 11 x64 与 macOS 14+ arm64/x64。Linux 返回明确的不可用原因。悬浮窗只订阅会话帧与状态，Agent 只调用标准服务 API；两者都不接触平台句柄。

## 多窗口追踪

桌面会话固定到打开时选择的真实窗口及进程实例。出现聊天独立窗口、模态框或另一个同进程窗口时，不跟随最前窗口；原窗口不可采集时返回原目标的状态，不把另一个窗口冒充原窗口。切换必须明确选择准确的 `targetId`、打开对应会话并重新观察；旧窗口的观察 ID 和输入基线不能用于新窗口。

`desktop_session_window_candidates(sessionId, waitMillis)` 只读返回同一真实应用和进程实例的所有候选，宿主最多等待 3000 毫秒，不增加模型轮询。它不自动选择、授权输入或结算未知效果。后台清单按所有者隔离，在有效会话期间有界刷新，记录发现、打开会话、隐藏、重新出现、不可用和确认关闭。清单消失只记不可用；只有准确原生存活检查证明窗口消失才记关闭。

Java 平台适配器直接读取系统父窗口关系证明。macOS 使用公开辅助功能关系及唯一窗口匹配，Windows 使用原生 owner；无法证明时保留 UNKNOWN。相同 PID、标题、位置或出现顺序不构成父子证明。实际派发操作后新观察到的同进程候选记录来源调用、来源窗口和 `OBSERVED_AFTER`，其含义始终是“操作后观察到，因果未知”；不会声称该操作创建了窗口。未派发动作不能建立来源关联，多候选全部保留。

会话“执行记录”的交互记录按应用 → 进程实例 → 真实窗口聚合，只有已证明的原生父关系才嵌套显示；操作后的候选关联独立展示。生命周期记录通过稳定事件 ID 幂等写入，异步持久化失败可从服务有界历史重放。历史不恢复旧句柄、不替代当前观察、不作为业务完成证明。平台代码与参数布局随 Java 应用构建，启动只加载操作系统库，不加载历史自建桌面库。

纯同应用只读合同的跨窗口正文验收另行核对：完整候选清单绑定同一进程实例，显式打开目标窗口，随后提交目标窗口的完整正文条件证明，并保持原条件顺序。该路径不核销输入或未知效果；包含输入的合同继续执行原有动作证据验收，不能仅凭窗口追踪关系判定完成。“点击 A 后在 B 验收业务效果”仍需专门跨窗证明契约，当前可以追踪、明确选窗和观察 B，但不能用 B 的帧替代 A 的动作效果证明。

## 分层与装配

- `com.javaclaw.desktop.api.DesktopSessionService`：发现目标、打开会话、按需截图、异步操作、前台接管、帧、状态与操作事件订阅，以及关闭作用域或工作区。`actions(owner, sessionId)` 受同一会话归属约束，事件含动作编号、动作种类、开始／结束、结果、派发分类、原因、窗口代次与时间戳；不含输入文本、键名、坐标或原生句柄。
- `com.javaclaw.desktop.spi.DesktopPlatformProvider`：平台能力探测、目标发现、创建原生会话。Spring 根配置注册 Windows 和 macOS Provider，服务按探测结果选择可用实现。
- `com.javaclaw.desktop.ffm`：平台能力、会话、参数校验与调度均由 Java 实现，`macos.MacDesktopApi` 与 `windows.WindowsDesktopApi` 通过 JDK 25 FFM 直接调用系统库。macOS 捕获使用 ScreenCaptureKit 的公开截图接口，Objective-C 消息与异步完成回调由 Java FFM 绑定；Windows 使用 Windows Graphics Capture，经过 Direct3D 11 staging 纹理读取 BGRA 帧。平台探测和真实系统返回决定可用能力，不依赖项目自建库、生成绑定或外部进程。
- `com.javaclaw.desktop.agent.DesktopSessionTools`：新 Agent 工具；旧 `desktop_probe`、`desktop_capture`、`desktop_click` 等前台 Computer Use 工具及 CLI 适配器已删除。`sys_*` 截图和键鼠工具保留原有行为，不受新开关放宽。
- `desktop_session_observe`：从所属会话读取最新实时帧，直接在内存中交给运行作用域内的视觉模型；返回原帧尺寸、窗口代次、内容修订、`observationId`、有界辅助功能元素及视觉目标。不接受任意图片路径。视觉识别失败时不会提交本次观察，也不会解除结果未知的输入门禁。`desktop_session_snapshot` 仍可把图片保存到应用内目录供用户查看。
- `com.javaclaw.ui.javafx.desktop.DesktopPreviewWindow`：置顶预览窗，显示当前应用／弹窗标题、最近操作及结果、暂停原因、停止与前台接管入口。静态结构采用 FXML，颜色复用应用主题令牌；窗口支持普通、最大化和迷你悬浮三态。原始帧在 FX 线程外按视口尺寸及屏幕像素密度缩放，只保留最新帧并限制刷新频率；调整尺寸时即使没有新帧也会重新缩放，暂停或关闭时清除缓存。多个窗口错位排布，前台输入前暂时隐藏预览，避免挡住目标。

后续平台只需实现 Provider SPI 并注册 Bean；公开 API、Agent 编排和 JavaFX 预览不需要平台分支。

## 悬浮预览操作

标题栏的减号切换为保留实时缩略图的迷你悬浮窗，再次点击还原；方框按钮在当前屏幕可用区域最大化，再次点击恢复普通尺寸。双击标题栏或画面也可切换最大化，Escape 恢复普通窗口，系统快捷修饰键加 M 切换迷你状态。拖动标题栏移动窗口，普通状态下拖动右下角调整尺寸。迷你状态保留会话状态和关闭入口；关闭按钮与“停止”都会结束该桌面会话。

## 会话规则

1. “通用设置 → 电脑应用访问”默认关闭。开启时会检查并请求系统权限；未就绪则保持关闭。macOS 请求屏幕录制并提示开启辅助功能权限；Windows 检查 Windows Graphics Capture 与输入能力，该平台没有统一的应用授权弹窗。保存开关后，智能体可直接使用 `desktop_session_*`，包括前台接管；手动审核模式也不再逐工具弹窗。会话服务仍在每次观察和输入前检查开关及系统权限。`sys_*` 维持原有审核。关闭开关会阻止新操作并释放现有会话；运行中撤销系统权限会暂停会话并清除最新帧。
2. 目标发现返回不含 HWND/原生指针的 ID。ID 包含进程创建实例；原生打开时再次核对，若进程在发现后重启或 PID/窗口 ID 被复用，则要求重新发现。无法读取进程实例的窗口不参与发现。会话仍绑定工作区、会话作用域和运行来源。
3. 每次动作须带本会话最近一次已提交的 `observationId` 和窗口代次。辅助功能元素及视觉目标均有观察专属的目标 ID；服务核对窗口、目标区域与周边像素、元素能力及坐标边界，允许目标区域外的动画变化，并把最新修订号交给平台适配器复核。令牌只供一次动作使用。旧持久化调用缺少观察 ID 时只要求重新观察，不会重放输入。截图中的控件文字不作为可信指令或权限来源。
4. 会话默认使用 `BACKGROUND_STRICT`，只通过公开 AX／UIA 控件能力派发后台语义输入；不支持的控件或动作明确拒绝。用户在设置中选择 `SYSTEM_EXPLICIT` 后，新会话才使用 Windows `SendInput`／macOS CoreGraphics；辅助功能目录和视觉目标用于定位。会话输入策略不可自动提升或切换，`control=false` 只读。已有派发和未知效果不能通过换通道或重开会话重试。
5. 系统输入使用已开启的设置授权。前台准备会隐藏悬浮预览并取得确切目标窗口焦点，观察和 Agent 规划期间的输入租约最长 180 秒；租约结束或动作后显示预览，并仅在用户未主动切走时恢复先前焦点。发事件前核对目标实际获得输入且点击点未被其他窗口遮挡。按位置聚焦输入框、滚动区域；输入接口成功不等于业务效果成功，后者须由新的画面观察确认。
6. 输入是否完整派发无法确定时，返回 `UNKNOWN / MAYBE_SENT`，暂时停止该目标后续输入。原生调用结束并经过稳定时间后，同一实际目标的新画面须成功完成视觉解释与观察提交；完整宿主调用与收据再建立后续输入基线。框架 `RunControl`、持久 `JdbcRunStore`、`ManagedSession` 与 Cursor 均检查新基线，允许基于该新 `observationId` 决定后续动作。原业务效果仍为未知，`SATISFIED` 仍须严格验收；旧帧、无效或外来观察、未配对收据及展示文字不能解除保护。重新打开仅恢复句柄，Agent 应先观察当前状态，不得盲目重复原逻辑动作。双击部分派发和输入接口异常同样按未知处理。兼容后台文本语义写入可能替换控件的全部当前值。
7. 采集方只保留最新帧，帧订阅者每人最多积压一帧；操作事件订阅者有固定上限的队列。最小化、不可见、失帧或权限撤销会清除实时画面并标记暂停，迟到的旧帧不能在恢复时重新显示。工作区切换、会话删除或应用退出会关闭原生会话并取消悬浮窗订阅。

## macOS 控件定位与失败恢复

辅助功能目录按公开能力只读采集，不依赖具体应用名，不开启
`AXManualAccessibility` 或 `AXEnhancedUserInterface` 等应用内部开关。
目录遍历有节点、时间和输出预算，优先保留可操作控件；观察结果包含遍历
计数、截断情况和原始 AX 错误，不包含输入框当前值。

显式系统输入保留观察中的 AX 目录定位，点击通过系统事件派发。
默认后台路径的单次左键点击使用观察中的 AX 元素令牌，执行前复核进程实例、
目标窗口、控件角色、动作能力、位置和目标区域像素。重新读取目录会使旧
元素令牌失效。目标区域之外的动画不必使控件失效；目标变化则要求重新观察。
其他手势和视觉定位使用各自的能力检查与输入路径；参数布局与平台调用均在 Java 中维护。

后台 AX 单击被接受后，如果经过稳定时间的新解释帧与派发前完整像素一致，
且实际窗口、代次、内容版本及唯一控件均相同，重复单击会在原生派发前被拒绝。
新拒绝为 `NO_PROGRESS / NOT_SENT / effect=NONE`；第一次已派发点击仍保留
未知业务效果，不据此自动补发前台鼠标输入。画面变化、不同控件、其他输入
和前台操作不进入这一重复点击判定。

交互子 agent 在下一次模型调用及点击派发前检查宿主日志，收到该拒绝后以
`DESKTOP_NO_PROGRESS` 结束无进展执行并返回未满足条件和待核实操作。
恢复时仅对完整、可信且绑定实际窗口的历史观察作兼容判定，截断的 AX 目录
不能证明控件唯一。句柄或观察 ID 更新本身不算任务进展，已有预算、权限、
跨模式未知效果保护和验收要求继续生效。

前台准备分别确认目标窗口和应用焦点，鼠标事件派发前在实际点击点检查
遮挡。窗口中央被遮挡不直接代表目标控件被遮挡；真实点击点不属于目标
窗口时，失败诊断会指出遮挡窗口的进程、窗口 ID 和层级。后台路径失败
与前台准备失败的原因会一同保存，以便区分权限、AX 通信、能力和窗口问题。

启动成功或启动结果未知后，恢复流程先调用 `desktop_session_targets` 发现
窗口，再打开或复用会话并观察。跨 Run 继承未知输入且缺少当前句柄时，
同样按 `targets → open → observe` 建立新基线，不清空历史记录。观察原始数据、
收据与后续输入须匹配当前会话、目标、观察 ID 和窗口代次，采集时间须晚于旧输入。
重新启动应用不能解决点击遮挡；启动保护、输入基线及业务效果核销由运行框架分别处理。

## 点击派发与后续观察

每个动作请求都分配会话内递增的 `actionId`，前置拒绝也产生终态。画中画在派发前
显示“准备操作”，不模拟已按下；`NOT_SENT` 清除目标标记，`SENT` 显示中性标记
一秒，`MAYBE_SENT` 显示橙色标记两秒。终态独立携带派发分类，旧事件不能覆盖新动作，
暂停、关闭及窗口代次变化会清除反馈。标记表示动作目标和派发状态，不代表系统鼠标位置。

点击守卫使用纯 Java 实现，复用已有的捕获与输入桥接接口，不需要额外原生符号或
C++ 策略文件。Java 比较观察与最新帧的目标区域及八像素边距，并复核窗口、进程实例、
代次、几何与新鲜度。每次区域数据最多 8 MiB，超限要求缩小目标；区域比较允许区域外动画。
Java 平台适配器通过 FFM 直接负责系统输入和公开控件派发，并保留身份、焦点和点击点归属检查。
后台控件令牌仍绑定原观察版本，版本变化可能要求重新观察。双击由 Java 平台适配器编排系统事件。
任何已派发部分动作的后续失败均保留未知结果，不能重放部分动作。Java 校验与操作系统
实际接收输入之间仍存在时间间隔，不能据此承诺界面不会在其间变化。
文字、按键与滚动同样由 Java 平台适配器通过系统 FFM 调用执行。

点击回执完成后，宿主在下一轮推理前通过普通工具 Gateway 自动执行一次独立的
`desktop_session_observe`。仅 `SENT`／`MAYBE_SENT` 触发，拒绝不自动重发。自动观察
要求帧采集时间严格晚于宿主点击回执时间再加 150 毫秒，取帧最多等待三秒，等待期间
不占用窗口或会话锁。随后复用视觉模型、解释提交及独立观察回执，交给主模型判断效果。
观察失败保留点击派发分类；新截图或画面变化不会自动把未知业务效果改为成功。
恢复运行可继续只读观察，不能重放点击。

## 应用目录与发行

便携应用根包含只读签名 `runtime/`、可写 `plugins/` 和 `data/`。数据、截图、日志、Playwright 资产及临时文件都在该根下；旧数据和插件经暂存、内容校验后复制迁移，原件保留。详情见 [便携应用目录](portable-layout.md)。

源码开发使用 JDK 25 和 Maven 构建 Java 应用，不需要 C／C++ 编译器、jextract、
平台 SDK 头文件或单独桌面库。启动 JVM 需要 `--enable-native-access=ALL-UNNAMED`；
Maven 测试、JavaFX 启动配置及便携装配脚本已设置此参数。系统屏幕录制、辅助功能
等权限仍按平台实际要求检查，授权不足不会自动尝试历史库或另一个输入通道。

发行装配与签名方式见 [Java 桌面能力发行说明](desktop-native-release.md) 及
`scripts/assemble-portable-macos.sh`、`scripts/assemble-portable-windows.ps1`。
脚本只装配 Java 应用和运行时并签署应用／内置 Java，不再构建、复制或签署项目
自建桌面库。旧发行目录中的历史库不参与当前平台探测与执行。
