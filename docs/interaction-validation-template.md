## Supported contract ordering

The executor accepts browser and desktop criteria as one contiguous block in the frozen parent contract. Other tool criteria may appear before or after that block. Browser-to-desktop work within the block is supported. Interleaved work such as `browser.read → file.write → desktop.type` is rejected with `INTERACTION_CONTRACT_INTERLEAVED` before a new interaction child starts. Amending such a parent contract is also rejected before amendment planning or contract changes. The host preserves the original criterion order; this version does not split an interleaved contract into multiple delegations or silently move other-tool work outside the interaction block.

Cross-backend work is conservatively limited after an input. `ACCEPTED / SENT` with an unproved business effect is distinct from uncertain delivery (`UNKNOWN / MAYBE_SENT`). After selecting another backend, either backend's next side effect is blocked until strict host proof verifies all pending business inputs. Switching back, AMEND, a new round, restart, ordinary observation, a model checkpoint, or a user claim alone cannot clear this protection. Delivery uncertainty remains independently blocked and is never cleared by business-stage proof.

The original predeclared adjacent desktop click → view proof remains available. C3 additionally supports `core.interaction.stage_verified` for a source Run's single original, unrevised host V3 contract: an original supported observation predicate must be explicitly FALSE before the complete ordered `ACCEPTED / SENT` input set and explicitly TRUE afterward. Verification rechecks the original contract sequence/hash, earlier acceptance conditions, every pending invocation, non-overlapping timing, fresh input baselines, exact actual surface identity and original target. The durable event lists only the covered invocation IDs. Native click/type/key/scroll and supported browser input stages are therefore not categorically blocked after a mode change; they require this proof. Missing, overlapping, foreign-object, uncompleted or delivery-unknown inputs prevent it.

Browser-stage predicates are limited to original nonempty `requiredTextFragments` for a complete main-document visible BODY literal conjunction; an original subject, when present, is also required. URL, document and stable Page/Context identity are captured with the full body. Historical subject-only criteria, element/iframe reads, truncated text, unreadable content and suspected secrets cannot establish FALSE. Native stages use explicit TRUE/FALSE/UNKNOWN outcomes from the existing controlled visual observation, not a new model call. FALSE requires visible main-content counter-evidence, TRUE must agree with the existing positive evidence, and both require the existing confidence/geometry checks. The captured actual window/session/generation must remain the same and content revision must increase. This is visual judgment, not deterministic host text verification; missing or ambiguous evidence remains UNKNOWN.

Arbitrary JavaScript and deferred browser dialog handlers do not support stage release. Native transitions to a different actual window or dialog do not obtain proof from a shared PID, application or logical target. Changed contracts, absent original predicates and lost identity continuity after restart also remain conservative. Unsupported write-then-cross tasks stop with `CROSS_MODE_BUSINESS_UNVERIFIED` and unmet conditions. Read/navigation-then-calculation remains in scope; these safeguards do not add dynamic data-binding or arithmetic verification and do not establish support for arbitrary write-then-cross workflows. C3 compiled successfully; the supplementary proof-release checks below remain unexecuted until actual GUI evidence is recorded.

- Export `direct`, `descendants`, and `aggregate`; compare **aggregate** provider attempts, input/output tokens, and estimated cost. Do not add the aggregate to the child totals again.
