# JavaClaw 4.0 升级说明

JavaClaw 4.0 将模型的完成申请、工具调用状态、效果收据与最终任务结果分开记录。只有独占模型调用批次的 `harness_submit_decision` 控制调用能提交模型决策；参数包含 `decision`、`userMessage`、`evidenceRefs` 和 `unmetCriterionIds`。普通回复及工具展示文字不再决定任务状态。插件通过进程内 Plugin API 4.0 接入，3.x 插件不能加载。

`evidenceRefs` 是可选的证据编号数组，只能复制工具结果中宿主生成的 `evidenceRefs`；工具名称、结果描述和失败回执不能作为编号。没有适用证据时可省略或使用 `[]`，例如因访问开关关闭提交 `NEEDS_INPUT` 或 `BLOCKED`。无论模型是否附带编号，完成申请仍由宿主独立验收。决策参数被拒绝时，反馈提供具体 `reasonCode`、可用证据编号及验收条件编号；模型应修正控制参数，避免为此重复执行业务操作。纠正后仍无有效决策时，暂停事件和界面保留具体拒绝原因。

“继续”等承接指令通过有界的历史用户请求解析任务目标，并始终保留本轮输入的优先级。按需规划漏选业务工具时，模型可以通过授权工具目录发现所需能力；目录仍遵守本轮权限、调用次数和工具上下文预算。桌面规划每次读取当前保存的电脑应用访问开关，系统权限在探测前标记为未知，避免沿用旧助手回复中的权限结论。工具审批后恢复时，已完成的规划在原有目标和授权范围内复用，可变运行状态单独刷新，避免重新执行已完成的操作。

Computer use 的探测、观察、动作、错误与会话恢复接入版本化结构结果。持久回执派生会话 cursor，启动后发现窗口、打开后观察、输入后再观察等必需阶段由宿主先提供所需工具，可选轻量规划格式异常不会再挡住这些阶段。未知输入后，完整宿主调用与收据绑定的新观察可建立后续输入基线，原业务 `UNKNOWN` 保留，`SATISFIED` 仍须严格验收。旧原生会话过期或新 Run 缺少当前句柄时，按 `targets → open → observe` 恢复；旧帧不得重放，也不得凭基线盲目重复原逻辑动作。内部 ModelTask 严格归一化单个 JSON 包装，拒绝辅助模型执行 native tool calls。完整协议、调用链与恢复约束见 [Computer use 调用链](computer-use-protocol.md)。

按需规划的 `sourceIds` 只能选择本次 `candidates[].id`，`toolIds` 只能选择 `toolCandidates[].id`。工具成功凭证 `evidenceRefs` 不属于上下文候选。没有上下文候选时，宿主清空误填的上下文引用；候选存在时，错误选择允许一次持久化纠正，仍不能读取未提供、未授权或超出预算的上下文。

## 暂停后的输入与期限

暂停后的普通新指令会结束旧任务并建立新的 Run、契约和预算。明确的完整继续/重试指令（如“继续”“重试本轮”、`continue`、`resume`、`retry`），以及与旧请求完全相同的输入，继续原 Run；附加文件不会被当作仅含继续指令的输入丢弃。等待补充输入时，回答继续原 Run。集成方可以通过可信请求属性 `framework.turnIntent=NEW_TASK` 或 `CONTINUE` 明确指定输入用途，避免依赖应用名称或语言推断。

恢复始终使用原 Run 的截止时间、调用账本和效果记录。已过期的持久任务在恢复时结束为 `RUN_TIMEOUT`，不重置预算，也不再进入业务执行。新请求替换旧任务记为 `TASK_SUPERSEDED`；未知副作用的记录仍保留。界面分别显示运行终止原因与任务验收状态，超时不会被旧契约的未验证提示掩盖。

新 Run 只继承同一会话及其挂接子任务的效果保护与旧观察消耗记录，不继承旧预算、调用计数、审批或输入帧。恢复包含终态任务的持久记录；取消、失败、超时本身不能证明输入未发送。未知桌面输入按实际目标保护；同一目标须先取得可用的新宿主观察基线，不同目标仍可执行。`RunControl`、`JdbcRunStore`、`ManagedSession` 与 Cursor 分别校验当前会话、目标、观察 ID、窗口代次及输入后的采集时间；原生输入结束、视觉解释与观察提交均须成功。失效、外来、未配对观察和展示文字不能建立基线，也不清除历史未知效果。效果标识包含来源 Run，避免不同 Run 的同名调用相互覆盖或核销。

## 首次启动的数据处理

数据格式为 `4`。首次从格式 `3` 启动时，启动器先取得应用目录内稳定锁和旧实例数据锁，确认旧实例已退出，再清空**该应用目录自己的** `data/` 与 `plugins/` 内容。此操作不迁移旧数据库或插件，也不清理源码、`runtime/` 或应用目录外的文件。升级中断后，下次启动会继续完成清空；路径包含符号链接、格式未知或无法取得独占锁时，启动器拒绝清空。

升级会删除本机保存的工作区、会话、设置、插件及缓存。需要保留旧环境时，在首次启动 4.0 前自行复制整个旧应用目录；4.0 不会自动读取这份副本。

## 集成变更

- 自定义 `RunStore` 须实现 `scopeRuns(RunScope)`，返回精确工作区、用户和会话范围内包含终态任务的完整记录，供持久效果恢复使用；缺少该能力会明确拒绝执行。
- 插件描述符的 `apiVersion` 须为 `4.0`，进程内插件须重新编译。
- 工具返回 `ToolExecutionResultV1` 状态和独立的效果收据。展示文字不用于判断成功、失败或完成。
- SDD 提案、任务与验收规格分别以版本化 `proposal.json`、`tasks.json`、`specs.json` 判定状态；同名 Markdown 文件仅供阅读。
- 工具描述符必须具备宿主认可的权限和风险元数据。未登记的工具默认拒绝。
- 定时任务默认持续运行；只有明确配置为条件达成后停止，且 Harness 返回已验收结果时，才停用后续调度。
- 调度执行历史持久化 `SUCCESS`、`FAILURE`、`CANCELLED` 状态码；中文标签只在界面展示时生成。
- 浏览器元素目标使用明确的定位类型：`@e1` 为快照引用，`css:#id`、`xpath://button`、`text:文字`、`label:标签`、`placeholder:提示` 分别对应选择器和可见内容；无前缀值只按文字匹配。旧版裸 CSS 选择器（例如 `#id` 或 `body`）需加 `css:`，不会再靠字符串形状猜测类型。
