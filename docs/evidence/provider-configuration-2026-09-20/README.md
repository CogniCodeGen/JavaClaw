## 业务与兼容回归

- API / Protocol：连接、完整配置、预览代次、凭据意图、密封用途、方法目录与能力协商。
- App Server：新建和编辑的一次提交、凭据保留/轮换/清除、Provider 与 Credential 双版本冲突、最终锁内 CAS、候选失败与数据库回滚、容量继承、幂等重放和跨连接查询回执。
- 预览：临时密钥和精确版本已有密钥、取消零写入、共享容量、超时和响应上限、会话关闭取消真实 HTTP、来源版本冲突、脱敏错误分类；同时回归原 discovery。
- SDK：一次密封并冻结保存请求、预览和保存的独立用途、秘密清零、取消和中断、未找到回执继续保持未知，不自动另发保存。
- Desktop：新建/编辑/补全、目录失败后手动添加、多模型与纯向量模型、属性保留、禁用原因、草稿保护、迟到响应、会话失效、失败后重输密钥、保存不调用 `useModel`。
- 键盘：Esc 关闭无草稿窗口、Esc 放弃确认的取消路径、手动模型输入 Enter 只添加模型、提交期间 Esc 和标题栏关闭不能撤销已发送请求。

测试中的秘密均为固定假数据；截图入口 `ProviderConfigurationWindowEvidence` 不访问服务器、模型服务或凭据库。

## 真实限制

- 未在 Windows、Linux 或 macOS x64 上运行本轮原生 UI；不能据此宣称跨平台发布验收通过。
- 本机系统凭据设施专项测试及两项浏览器原生发布烟测因环境前提不满足而跳过，未宣称这些原生能力完成发布验收。
- 未用真实厂商账户进行模型推理或认证验收；显式联网验证仍是独立、可能计费的用户操作。
- 预览操作只在服务端内存中保留，受原目录读取生命周期和容量限制。断开后需要重新预览。
- 统一配置要求服务端协商 `core.provider-configuration.v1`，旧服务端需升级，不回退为多次分阶段写入。
- 未找到保存回执仍表示结果未知，页面保持原请求身份，不能将关闭窗口或重新密封作为撤销或重试。
