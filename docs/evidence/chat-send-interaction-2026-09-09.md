# 聊天发送交互修复

2026-09-09，macOS arm64、JDK 25、JavaFX 26.0.2。

## 行为与原因

输入框改为 Enter 发送、Shift+Enter 换行，保留 Ctrl/Cmd+Enter 发送。换行使用 TextArea 的选区替换操作，
保留光标与撤销；组合输入尚未提交时不发送或插入额外换行。按钮不可用时保留草稿，发送和回执不移动焦点。
输入框提示和可访问说明同步更新。

原有发送链只提交 busy 状态，没有本地用户消息；需要等待 turn/start 返回，再经过 Turn、审批及历史查询，
自己的消息才出现在记录中。服务端启动准备及同连接 RPC 排队都会反映成界面的等待时间。

现在通过本地校验后，在同一次 UI 状态提交中发布“你 · 正在发送”，后台继续使用原 SDK 请求。
收到回执后显示“已发送”，由同 Turn 的权威 USER 消息替换回显；不伪造 Item、sequence 或文件引用，
不依赖可能截断的摘要文本做去重。回执失败显示“发送未确认”，保留草稿与幂等身份，避免把回执丢失当成未提交。
终态启动回执也补读历史，以覆盖重试恢复已经完成的 Turn。

每次主动提交有独立展示尝试号，后端幂等键保持不变。即使失败中间帧被合并，快速重试仍会回到消息末尾；
普通确认与后台更新保持用户随后开始的阅读位置。Web 与简版都为回显预留一行，总窗口不超过500条。
上一轮未提交尾文排在新用户消息之前；新 Turn 接受后结束旧轮暂态展示，已有同 Turn 的新正文继续保留。
会话切换清理当前回显，迟到回执不能写入另一会话，也不能清除后来编辑的草稿。
