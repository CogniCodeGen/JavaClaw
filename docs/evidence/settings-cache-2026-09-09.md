# 设置页面缓存与工作区命名修复（2026-09-09）

## 重复查询来源

管理窗口原先在每次打开时读取工作区目录、激活当前页面，获得焦点后又重复执行同一组刷新。
模型、角色与权限页的激活协调器，以及工作区执行配置面板，也会无条件重新查询。
聊天配置虽然能识别连续相同的绑定，但离开再返回对话和窗口聚焦仍会重读。
页面注册表原先一次性构建全部设置页；导航时还会重建滚动容器。

## 复用及失效规则

- 设置页按首次访问创建，已访问页面及其滚动容器保留到管理窗口释放。
- 工作区目录、模型/角色/权限目录和执行配置的成功结果复用五分钟。期限用单调时钟判断，
  只在激活时检查，不增加后台定时轮询。
- 聊天按工作区与对话缓存完整配置、预览及保存版本，最多保留 32 个作用域。访问不延长有效期。
- 核心配置保存事件、重连、手动刷新使对应缓存失效。隐藏页面只记录失效，重新显示时读取。
  在途失效需要补读，旧响应不能把已失效配置重新放入缓存；失败结果不缓存。
- 扩展页面在同一工作区内复用成功页面、Schema、节点与空目录十五秒，保留原有可见页十五秒对账。
  事件、成功命令、作用域切换及重连仍刷新；分页和草稿保护沿用原状态机。
- 同工作区的提示词预览与优化草稿列表按需复用。保存版本和本地编辑草稿不被自动刷新覆盖。
- 凭据、授权有效性、审批、连接健康及任务进度仍按原实时机制读取；缓存不替代服务端执行校验。

当前核心配置通知只覆盖本 Desktop 成功写入，不能当作跨客户端服务端推送；因此保留有限期限及手动刷新。
缓存仅存在当前 Desktop 内存中，不写入个人全局设置。

## 工作区名称

模型配置向导的创建入口原先直接使用根目录名，缺少自定义名称步骤。现将目录名作为可编辑默认值，
通过统一样式的名称确认框获取最终名称，提交时去除首尾空白；取消或空白名称不创建工作区。
主窗口的创建入口原本已有名称输入，本轮未复现名称被覆盖；真实 Dialog 确认取值以及
Presenter → SDK 请求 → 当前工作区和目录回显的中文名称回归已通过。未将向导修复当作已经复现
所有入口的同类问题。
